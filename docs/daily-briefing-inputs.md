# Daily briefing input map

Issue #11 P1-B の実装前確認として、朝の画面が参照する入力と確認導線を整理する。

| 表示ブロック | 主な入力 | 空データ時 | 詳細導線 |
| --- | --- | --- | --- |
| 今日やること | 決算、候補、ニュース、開示、買い検討ライン、企業カルテ、戦略ルール、スコア、RSS失敗 | 優先タスクなし | 入力ごとの既存ページ |
| 重要イベント | `build_briefing()` の warning/danger/positive/negative | 注意イベントなし | 対象ページ |
| 最新材料 | ニュース・適時開示の各2件 | 新しい材料なし | ニュース／適時開示 |

`services.daily_briefing` と `components.daily` はすでにDBや取得処理から分離され、欠損値・空配列・同一対象の重複を安全に扱う。`tests/test_daily_briefing.py` とUIテストで、優先順位、件数制限、空状態、開示・戦略・企業カルテ入力を確認している。

次のP1-B実装では、日次更新の完了後にこの既存入力へ新しい通知経路を重ねず、更新結果を同じ受け皿へ反映する。ニュース要約などAI・有料APIを必要とする拡張は別タスクとして、人間承認境界を維持する。
