# 決算後の状態自動整理

## 現在の境界

- `earnings_date_info` は過去イベントを `発表済み` として表示する。
- `next_earnings_by_stock` は過去日を次回イベントに選ばないため、古い決算接近警告を次回予定として再利用しない。
- `earnings_candidates` は正式イベントとは分離され、`pending` 候補だけが明示確認の対象になる。
- `build_post_earnings_state` は過去イベント、次回正式イベント、次回候補を分離するview modelであり、DBを変更しない。

## 安全な遷移

1. 過去の正式イベントは履歴として保持し、削除・書き換えない。
2. 次回の正式イベントがあればそれを表示する。
3. 次回の正式イベントがなければ、日付が未来の `pending` 候補を確認待ちとして表示する。
4. 候補の正式イベント化は既存の明示承認処理だけが行う。

自動テストでは、過去イベントの接近警告抑制と次回候補の表示境界を確認する。実データの決算発表済み判定や候補日妥当性はHuman Actionとして残し、自動売買や投資判断には接続しない。
